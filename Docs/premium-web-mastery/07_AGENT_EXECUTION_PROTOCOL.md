# 07 — AI AGENT EXECUTION PROTOCOL

## Purpose

Paste this file into an AI coding agent alongside the other design docs. It converts the philosophy into an implementation protocol.

---

## DESIGN MISSION

Redesign the supplied web application as a **premium, calm, high-craft software product**.

Do not blindly copy Apple, Notion, Linear, or another reference. Extract their principles and create an original visual system appropriate to this product.

The final result must feel:

**expensive, intentional, editorial, technically sophisticated, calm, trustworthy, product-led, and polished.**

---

## STEP 0 — INSPECT BEFORE CODING

Before changing anything:

1. inspect the current app structure
2. identify every major route/page
3. identify the primary user journey
4. identify the strongest existing functionality
5. inspect current assets, logos, imagery, and icons
6. identify technical constraints
7. identify reusable components
8. identify existing design tokens
9. identify broken or low-quality areas
10. establish what should be preserved versus redesigned

Do not begin by generating random UI.

---

## STEP 1 — WRITE A DESIGN BRIEF

Internally produce:

- target audience
- desired emotional response
- product promise
- visual personality
- content hierarchy
- primary conversion goal
- primary product proof
- dominant layout pattern
- dark/light strategy
- accent strategy

Use the reference philosophy as a lens, not as a template.

---

## STEP 2 — CREATE THE TOKEN SYSTEM

Before styling dozens of components, define:

- colors
- typography
- spacing
- radii
- borders
- shadows
- surfaces
- control heights
- motion durations
- easing

Prefer CSS variables or the project's existing token system.

---

## STEP 3 — BUILD THE VISUAL FOUNDATION FIRST

Implement in this order:

1. page substrate
2. container/grid
3. typography
4. navigation/chrome
5. primary CTA
6. product showcase surface
7. cards/sections
8. forms and controls
9. micro-interactions
10. decorative atmosphere

Do not build decoration before hierarchy is working.

---

## STEP 4 — REDESIGN THE HERO

The hero must immediately communicate:

- category
- audience
- transformation
- credibility
- action

The visual hierarchy should normally be:

headline > supporting claim > CTA > product evidence

The product visual should feel like a valuable object, not an image inserted below the fold.

---

## STEP 5 — REDESIGN THE PAGE AS A STORY

Use the narrative model:

**recognition → evidence → worldview → capability → proof → trust → conversion**

Do not create repetitive feature cards simply to “fill the page.”

---

## STEP 6 — MAKE THE PRODUCT ITSELF BEAUTIFUL

Where a real app interface exists, prioritize it over generic illustration.

Improve:

- information hierarchy
- density
- labels
- alignment
- empty states
- loading states
- status indicators
- microcopy
- interaction feedback

Marketing quality should emerge from product quality.

---

## STEP 7 — ADD MOTION LAST

Start with a static version that already looks premium.

Then add:

- subtle entrance choreography
- meaningful hover states
- product interaction demos
- section reveals
- micro transitions

Respect reduced motion.

---

## STEP 8 — RESPONSIVE CRAFT

Desktop is not merely shrunk mobile.

For each breakpoint explicitly decide:

- type scale
- content width
- navigation behavior
- stacking order
- screenshot crop
- CTA arrangement
- card density
- section spacing

Test at narrow mobile widths and wide desktop widths.

---

## STEP 9 — POLISH PASS

Inspect:

- one-pixel misalignments
- inconsistent radii
- inconsistent icon sizes
- weak hierarchy
- unreadable muted text
- over-bright borders
- excessive shadows
- overly generic gradients
- excessive animation
- inconsistent hover states
- unnecessary copy
- awkward line breaks
- bad mobile wrapping

A premium redesign is usually won during this pass.

---

## STEP 10 — QUALITY GATE

Do not call the redesign finished until:

### Visual

- layout hierarchy is obvious within 2 seconds
- type looks intentional
- spacing has a consistent rhythm
- surfaces have coherent depth
- CTA hierarchy is clear
- no obvious template repetition

### Product

- important workflows are easier to understand
- realistic product states are shown
- states and errors are designed
- UI density feels deliberate

### Interaction

- hover/focus/active states are consistent
- motion is restrained
- keyboard behavior is reasonable
- reduced motion works

### Engineering

- no unnecessary dependencies
- no broken routes
- no console errors
- responsive layout works
- images are optimized
- animations do not cause obvious jank

### Accessibility

- keyboard focus is visible
- text remains readable
- controls have usable target areas
- important information does not depend only on color or motion

---

## CODING BEHAVIOR

When making a redesign decision:

**Prefer the simplest implementation that creates the intended perceptual result.**

Do not introduce a library merely for a decorative effect.

Do not replace existing working architecture without reason.

Do not create a giant monolithic component just to move quickly.

Do not hard-code dozens of unrelated values when a token system would work.

Use reusable components and semantic tokens.

---

## VISUAL SELF-CRITIQUE LOOP

After each major page pass, evaluate:

1. What is the focal point?
2. Is the visual hierarchy clear?
3. Does the page look expensive without looking decorated?
4. Does the interface feel like a real product?
5. Is there enough negative space?
6. Is any section repetitive?
7. Are the weakest elements dragging down the rest?
8. Is the accent overused?
9. Would one fewer effect improve the design?
10. Does the mobile version preserve the same philosophy?

Make corrections before moving to the next page.
